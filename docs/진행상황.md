**middleware.ts 버그 하나 더 잡음(이번 라운드에서).** icon/apple-icon/

**데모 시드 버그 수정함 (이전 라운드) — 재시도 결과 아직 확인 못 받음.**

### 플랫폼 최고관리자 (`/platform`)

학교 admin(교감·부장)과 다른 개념. **어느 학교에도 속하지 않는 계정**으로,
새 학교를 열고 기존 학교에 관리자를 지정할 수 있다. `lib/security/platform.ts`
(`isPlatformAdminEmail`, `requirePlatformAdmin`), `app/platform/*`,
`lib/platform/create-school.ts`(CLI·화면 공유 로직).

**사용자가 아직 안 한 것 — 다음 세션에서 확인:**
1. Supabase 대시보드 → Authentication → Add User → 본인 이메일(대화 시스템
   컨텍스트에 `dungst.me@gmail.com`으로 나와 있었음, 실제 쓸 이메일 재확인 필요)
   + 비밀번호, **Auto Confirm User 체크**
2. Vercel 환경변수에 `PLATFORM_ADMIN_EMAILS=<그 이메일>` 추가 → Redeploy
3. `/login`에서 그 계정으로 로그인 → 자동으로 `/platform`으로 감
4. `/platform`에서 새 학교 열기 또는 기존 학교(한빛특수학교)에 관리자
   지정해보기로 동작 확인

## 만들어진 것 (Phase 0~1 완료, 커밋 `e523ed2`)

원래 계획은 `/root/.claude/plans/magical-imagining-garden.md` 에 있음

### 확정 설계 결정
- **가명처리**: `students` 테이블에 실명·생년월일·연락처·진단명 컬럼 자체가 없음. 학번 + 별칭만
- **Supabase**: Postgres + Auth + RLS, 서울 리전
- **초대제 가입**: 공개 회원가입 없음. 관리자가 초대 → 토큰(해시 저장, 72시간 만료) → 비밀번호 설정
- **멀티테넌트**: 전 테이블 `school_id` + RLS. 학교 개설은 화면이 아니라 `npm run school:new`(서버 키 필요) — 닭-달걀 문제 때문
- **시각 비교는 분(minute) 단위**: 초등 3교시(10:40~11:20)와 고등 3교시(11:00~11:50)는 교시 번호가 같아도 겹침. `lib/scheduling/time.ts` 가 유일한 비교 통로
- **이중예약은 DB가 막음**: `room_reservations`에 PostgreSQL EXCLUDE 제약. 애플리케이션 검사만으로는 동시 요청 경쟁 조건을 못 막음
- **Gemini는 무료 키 전제**: 도입 시(Phase 4) 유료 전환 대신 4겹 방어 — 템플릿 폼 입력(이름 칸 없음) → 자유 텍스트만 마스킹 왕복(`lib/security/pii.ts`) → 사람 최종 확인 → 주민번호·계좌번호 강제 차단. 학생 이름은 앱에 명렬표가 없어 자동 탐지가 원리상 불완전 → 사람 확인이 필수 경유 단계

### 이번 라운드에서 잡은 실제 버그 3건
1. 충돌 검사에서 "같은 수업을 옮기는 것"의 판정이 느슨해 **다른 교사가 같은 학급을 같은 시각에 잡아도 통과**됨 → 담당 교사 일치까지 확인하도록 수정

## 무료 플랜 수용 규모 (2026년 기준, 세션에서 조사함)

| 항목 | 한도 | 이 앱 기준 체감 |
|---|---|---|
| Supabase DB | 500MB | 학교 수십 곳 분량, 병목 아님 |
| Supabase MAU | 50,000명 | 학교 수백 곳 분량, 병목 아님 |
| Supabase 프로젝트 유휴정지 | 7일 무접속 시 | 운영 중이면 해당 없음 |
| **Vercel 대역폭** | **100GB/월** | **가장 먼저 걸림** — 대략 학교 20~40곳·교직원 1,000~2,000명대에서 빠듯해질 것으로 추정 |
| Vercel 함수 실행시간 | 60초(기본)/300초(Fluid Compute) | `/api/demo/seed`(maxDuration=300)에 해당. Fluid Compute 미적용 시 시드가 타임아웃 날 수 있음 — 배포 후 실제로 확인 필요 |
| **Vercel Hobby 약관** | **개인·비상업적 용도로 제한** | 여러 학교가 정식 업무로 쓰면 기술 한도 이전에 **약관상 Pro 전환이 맞음** |

결론: 시범 운영(학교 1~수개)은 무료로 충분. 정식으로 여러 학교에 배포하면
Vercel 대역폭보다 **Hobby 약관(비상업적 용도)**이 먼저 걸리는 제약이라는
점을 사용자에게 이미 안내함.

## 다음 세션에서 사용자에게 확인할 것

1. 데모 시드 재시도 결과 (시각 겹침 버그 수정 후 처음 시도)
2. `supabase/schema.sql` SQL Editor 실행 여부 (명시적으로 확인 못 받음)
3. `/platform` 부트스트랩 — Supabase Auth 계정 생성 + `PLATFORM_ADMIN_EMAILS` 등록 여부
4. `/api/demo/seed`가 Vercel Hobby에서 실제로 300초까지 버티는지, 아니면 60초에 잘리는지
5. GitHub 기본 브랜치를 `main`으로 바꿨는지
6. `SEED_SECRET` 환경변수를 데모 확인 후 지웠는지
7. 실제 학교로 정식 운영할 계획인지 — 그렇다면 Vercel Pro 전환 시점을 미리 안내한 상태(약관상 이유)
