## 만들어진 것 (Phase 0~1 완료, 커밋 `e523ed2`)

원래 계획은 `/root/.claude/plans/magical-imagining-garden.md` 에 있음
(세션 로컬 파일이라 이 저장소에는 없음 — 아래가 그 요약).

### 확정 설계 결정
- **가명처리**: `students` 테이블에 실명·생년월일·연락처·진단명 컬럼 자체가 없음. 학번 + 별칭만
- **Supabase**: Postgres + Auth + RLS, 서울 리전
- **초대제 가입**: 공개 회원가입 없음. 관리자가 초대 → 토큰(해시 저장, 72시간 만료) → 비밀번호 설정
- **멀티테넌트**: 전 테이블 `school_id` + RLS. 학교 개설은 화면이 아니라 `npm run school:new`(서버 키 필요) — 닭-달걀 문제 때문
- **시각 비교는 분(minute) 단위**: 초등 3교시(10:40~11:20)와 고등 3교시(11:00~11:50)는 교시 번호가 같아도 겹침. `lib/scheduling/time.ts` 가 유일한 비교 통로
- **이중예약은 DB가 막음**: `room_reservations`에 PostgreSQL EXCLUDE 제약. 애플리케이션 검사만으로는 동시 요청 경쟁 조건을 못 막음
- **Gemini는 무료 키 전제**: 도입 시(Phase 4) 유료 전환 대신 4겹 방어 — 템플릿 폼 입력(이름 칸 없음) → 자유 텍스트만 마스킹 왕복(`lib/security/pii.ts`) → 사람 최종 확인 → 주민번호·계좌번호 강제 차단. 학생 이름은 앱에 명렬표가 없어 자동 탐지가 원리상 불완전 → 사람 확인이 필수 경유 단계

### 구현 완료
- **인증**: 로그인, 초대 수락, 미들웨어 세션 갱신, RBAC(`admin/manager/teacher/part_time/staff`)
- **8개 카테고리 메뉴** + 민감도 등급(`lib/security/sensitivity.ts`) — "학생 지원"(빨간 점)과 "수업 도구함"(노란 점)에 자동 경고 모달·배너
- **특별실 예약**(`app/(app)/rooms`): 과정별 주간 그리드, 충돌 검사(`lib/scheduling/conflicts.ts`), 추천 엔진(`lib/scheduling/recommend.ts`), 승인 대기
- **결보강**(`app/(app)/substitutions`): 결과 신청 시 시간표에서 자동 추출, 스코어링(`lib/substitution/score.ts`, 가중치는 DB에서 로드), 강사료 CSV 정산
- **학사일정**(`app/(app)/calendar`): 주간/월간, 범위별(전교/과정/학년/학급), ICS 구독
- **시간표 조회**, **관리자 화면**(초대·가중치 설정·학교 공용 Gemini 키·자유붙여넣기 토글·접속기록)
- **데모 시드**: `lib/demo/seed.ts` (로직) — `scripts/seed.ts`(CLI)와 `app/api/demo/seed/route.ts`(배포 후 브라우저용, `SEED_SECRET` 필요)가 공유
- **로그인 화면 데모 버튼**: 데모 학교가 실제 존재할 때만 노출. 4개 계정 원클릭 로그인
- **`/setup` 화면**: 환경변수 없을 때 미들웨어가 리다이렉트. 셋업 절차 + 데모 시드 버튼
- **`npm run school:new`**: 새 학교 개설 + 첫 관리자 초대 링크 발급 (CLI 전용)
- **테스트 59개** (Vitest): 충돌 검사, 스코어링, 시각 비교, PII 마스킹, CSV 인젝션 방지
- **CI**: typecheck/lint/test/build + service_role 키 클라이언트 번들 유출 검사

### 이번 라운드에서 잡은 실제 버그 3건
1. 충돌 검사에서 "같은 수업을 옮기는 것"의 판정이 느슨해 **다른 교사가 같은 학급을 같은 시각에 잡아도 통과**됨 → 담당 교사 일치까지 확인하도록 수정
2. PII 마스킹이 "학생의", "선생"을 이름으로 오탐, 휴대폰 번호를 계좌번호로 오인 → 불용어 목록 + 패턴 우선순위 조정
3. `Database` 타입을 `interface`로 선언해 supabase-js 제네릭 제약(`Record<string, GenericSchema>`)을 통과 못 함 → **모든 쿼리가 조용히 `never`로 무너지고 있었음**(런타임은 동작하지만 타입 안전성 전무). `type`으로 바꿔 해결
