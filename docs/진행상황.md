## Phase 4(수업 도구함) — 이번 세션 마지막 작업, 로드맵 완주

**DB 마이그레이션은 이번엔 없음.** Phase 4는 새 테이블이 필요 없었다
(쉬운글 안내문은 저장 안 함, 유튜브 캐시는 기존 `ai_cache` 재사용).
0007~0009는 여전히 밀려 있으면 적용해야 한다 — 위 절 참고.

**Phase 4: 수업 도구함 두 도구 완성. 계획서(magical-imagining-garden.md)의
Phase 4 설계 메모를 그대로 구현함.**

1. **쉬운글 안내문**(`/toolbox/easy-read`) — 이름 입력 칸이 없는 템플릿
   폼 + 안내사항 자유 텍스트 한 칸. "전송 전 미리보기"로 마스킹 결과를
   보여주고, 주민번호·계좌번호가 남아 있으면 아예 못 만들게 막음.
   `lib/security/pii.ts`(이전 세션에 이미 완성돼 있던 마스킹 왕복
   함수, 단위테스트 15개 통과)를 **이번에 처음으로 실제 기능에 연결함**.
   Gemini가 [[P1]] 토큰을 유지한 채 쉬운 문장을 만들면 서버에서
   원문으로 복원 — 토큰이 사라지면 실패 처리. 수준 1(그림 위주)은
   ARASAAC 공개 그림 상징 API로 핵심 낱말 그림도 함께 보여줌
   (`lib/ai/arasaac.ts`, 매칭 실패는 조용히 넘어감). 인쇄는 새
   라이브러리 없이 브라우저 인쇄 + `#notice-print-area` 전용 CSS
   (`:has()` 선택자로 그 카드만 남기고 나머지 숨김)로 해결.

2. **수업 자료 찾기**(`/toolbox/media`) — 과정·교과·수준·영상길이·주제만
   입력, 학생 이름 칸 자체가 없어 마스킹이 필요 없는 화면. Gemini로
   검색어 3~5개 생성 → YouTube Data API v3 검색(safeSearch=strict,
   videoEmbeddable, 한국어 우선) → videos.list로 재생시간 받아와
   길이 필터링(`lib/ai/youtube.ts`). 결과를 `ai_cache`에 7일
   캐시 — **이 테이블을 실제로 쓰는 첫 기능**(전에는 스키마만 있고
   아무도 안 썼음). 카드 클릭 시 youtube-nocookie 임베드로 그
   자리에서 미리보기(`next.config.ts`의 CSP `frame-src`가 이미 이
   도메인을 허용하도록 프로젝트 초기부터 설계돼 있었음 — 우연이
   아니라 Phase 4를 염두에 두고 처음부터 열어둔 것으로 보임).

**계획서 대비 의도적으로 뺀 것 (범위 조절):**
- **승인 채널 화이트리스트**(관리자가 유튜브 채널을 미리 승인해
  검색을 그 안으로만 제한하는 기능) — 새 테이블·관리자 UI가 또
  필요해서 이번 라운드에서는 뺐다. safeSearch·videoEmbeddable
  필터만으로 시작. 실사용해보고 필요하면 다음에 추가
- **부적절 영상 신고 버튼** — 신고를 받아도 갈 곳(관리자 검토 큐)이
  없으면 의미가 없어서, 어설프게 만드느니 아예 안 만들었다
- **쉬운글 안내문의 마스킹 결과 세부 토글**(계획서: "교사가 클릭
  몇 번으로 마스킹 대상을 추가·해제") — 전송 전 미리보기는 만들었지만
  항목별로 개별 해제하는 UI는 안 만들었다. 대신 안내사항 원문을
  고쳐서 다시 미리보기하는 방식으로 대체(더 안전한 쪽으로 단순화한
  것 — 개별 해제 UI가 없으면 실수로 위험한 걸 풀어줄 여지도 없다)
- **쉬운글 안내문 저장(자료함)** — 계획서에는 없었지만 자연스럽게
  떠오를 수 있는 기능. 지금은 만들 때마다 화면에 보여주고 인쇄하는
  일회성 도구. 저장이 필요하면 다음에 테이블을 추가

**검증**: tsc·eslint·vitest(59개)·build 통과. 두 화면 모두
devpreview-temp + Playwright로 데스크톱(1200px)·모바일(375px) 레이아웃
확인(가로 넘침 없음). **단, 실제 Gemini·YouTube API 키로 호출해
결과가 정확한지는 이 세션에서 검증 못 함** — 로컬 환경에 진짜 키가
없어 API 응답 파싱 코드가 실제 응답 형태와 맞는지 실물로 확인한 적이
없다. 다음 세션 또는 사용자가 실제 배포에서 반드시 확인 필요.

이로써 계획서의 **Phase 0~4가 전부 구현됐다.** 남은 로드맵은 Phase 5
(추가 제안 기능 중 선택)와, 애초 Phase 0에 있었지만 이번 세션 범위에서
계속 빠져 있던 엑셀/CSV 업로드·나이스 자동 동기화·웹푸시 알림·
Playwright e2e 테스트다. 자세한 목록은 아래 "아직 안 만든 것" 절 참고
(이번 세션 내용 반영해 갱신 필요 — 다음 세션에서 처리).

## Phase 3(PBS 기록) — 이전 세션 작업

**⚠️ 마이그레이션이 또 하나 밀려 있음.** `supabase/migrations/0009_pbs.sql`
을 Supabase SQL Editor에서 실행해야 한다(또는 `schema.sql` 전체 재실행).
`behavior_categories`·`pbs_records` 테이블과 RLS가 이 파일에 있다.
**없으면 `/support/pbs` 화면이 테이블 없음 에러로 통째로 안 뜬다.**

**Phase 3: PBS(긍정적 행동지원) 간소화 기록 완성.**
- 학급 → 학생(가명) → 행동유형, 탭 두세 번이면 기록 끝. "학생 지원"
  카테고리는 이미 `student_sensitive` 등급이라 진입 경고 모달·상시
  배너가 레이아웃에서 자동으로 걸림 — 이 기능 때문에 따로 만들 것은
  없었음(설계가 이미 이걸 위해 있었음)
- 기록 직후 "자세히 적기"로 선행사건(A)·결과(C)·메모를 펼쳐서 붙일
  수 있고, 이 자유 텍스트 3종은 `lib/security/crypto.ts`의
  `encryptSecret`/`decryptSecret`(원래 Gemini 키 암호화용으로 만든
  범용 AES-256-GCM 함수)를 그대로 재사용해 암호화 저장함
- 최근 8주 학교 전체 추세를 막대그래프로 보여줌. **구현 중 실제로
  버그를 하나 잡음** — flex 자식 요소에 명시적 높이가 없으면
  퍼센트 높이가 0으로 무너져 막대가 아예 안 보였다
  (`h-32 items-end` 컨테이너 + 퍼센트 높이 자식의 흔한 함정).
  Playwright 스크린샷으로 실제로 확인하다가 발견해서
  `h-full flex-col justify-end`로 고침 — 빌드·타입체크만으로는
  못 잡는 종류의 버그였다는 점을 기록해 둠
- 조회 자체(화면에 들어온 것)를 감사로그에 남김 — 계획서에 있던
  "조회·수정 전건 감사로그" 원칙을 이번에 처음 실제로 구현
- 새 학교 개설 시 기본 행동유형 7종(자리 이탈·지시 거부·소리
  지르기·물건 던지기·공격 행동·자해·기타) 자동 생성, 데모 시드에도
  학생 4명분 표본 기록을 채워 추세 차트가 비어 보이지 않게 함

**검증**: tsc·eslint·vitest(59개)·build 전부 통과. RecordPanel·
TrendChart·RecordList는 devpreview-temp 임시 라우트 + Playwright로
실제 렌더링 확인(위 막대그래프 버그를 이렇게 잡음), 확인 후 라우트
삭제·middleware 되돌림. **단, 실제 로그인 세션에서 서버 액션
(`recordBehavior`·`saveDetail`)이 실제 DB에 잘 쓰이는지는 라이브
환경에서 확인 못 함 — 마이그레이션 적용 후 다음 세션 또는 사용자
확인 필요.**

사용설명서에 "5. 학급·부서 예산"·"6. PBS 기록" 두 장을 새로 넣고
이후 장 번호를 6→8, 7→9, 8→10, 9→11로 재정렬함(목차·본문 내
"7장 참고" 같은 상호참조도 같이 고침).

## Phase 2(예산 관리) + 그 뒤 UI 버그 수정 라운드 — 이전 세션 작업

**⚠️ 사용자에게 꼭 알릴 것 — Supabase에 마이그레이션 2개 밀려 있음.**
`supabase/migrations/0007_events_open.sql`, `0008_budget.sql`을 SQL
Editor에서 실행해야 한다 (또는 `schema.sql` 전체 재실행 — 실 데이터
없는 학교라면 안전). **0008이 없으면 `/budget` 화면 자체가 테이블이
없어서 통째로 에러난다.** 0008은 `budget_lines`·`budget_expenses`
테이블과 RLS, `receipts` Storage 버킷·정책까지 한 파일에 들어 있다.

**Phase 2: 학급·부서 예산 관리 (`/budget`) 완성.**
- `budget_lines`(배정, 관리자만 생성) → `budget_expenses`(지출 신청,
  누구나 가능, `pending`으로 시작) → 관리자 승인(`approved`)해야
  배정액에서 실제로 빠지는 구조. 잔액은 저장하지 않고 화면에서 매번
  `배정액 - 승인된 지출 합`으로 계산
  (`app/(app)/budget/actions.ts`, `page.tsx`)
- 부서별 집행률 막대, 예산 항목 표, 지출 신청 내역(승인·반려·취소)을
  한 화면에 표시. Realtime을 `budget_expenses`에도 연결

**영수증: 처음엔 수동 첨부로 만들었다가, 사용자 요청으로 Gemini
Vision 자동 인식으로 바꿈.** 지출 등록에서 사진을 고르면 그 자리에서
업로드되고(`scanReceipt` 서버 액션) Gemini가 금액·날짜·상호명을 읽어
폼을 자동으로 채운다 — 결과는 제출 전에 사람이 확인·수정 가능.
`lib/ai/gemini.ts`가 **이 앱에서 Gemini API를 실제로 호출하는 첫
코드**다 (Phase 4 설계 메모에 있던 걸 예산 기능 때문에 앞당겨 만듦).
키는 개인 등록 키 우선, 없으면 학교 공용 키, 둘 다 없으면 업로드만
하고 직접 입력하도록 안내(신청 자체는 막지 않음). 호출 결과는
`ai_usage_logs`에 "누가 언제 어떤 키로 성공했는지"만 남김(서비스
롤로만 기록 — RLS상 일반 사용자는 못 씀). **실제 Gemini 키로
호출해서 진짜 영수증 사진에 잘 동작하는지는 로컬에서 못 미더워봄
(더미 키라 호출 자체를 안 함) — 다음 세션 또는 사용자가 실제 배포에서
확인 필요.**

**그 밖에 사용자가 스크린샷·요청으로 알려준 것들을 같은 라운드에서 처리:**
- 학사일정 캘린더: 초/중/고/전공과 과정별로 다른 색, 일정 클릭하면
  상세 모달(제목·기간·메모)이 뜨게 함
- 특별실 예약도 학사일정 "행사 넣기"와 같은 패턴으로 캘린더 위
  팝업으로 전환(배경 클릭·Esc로 닫기) — 예전엔 그리드 아래 계속
  붙어 있는 카드였음
- 사이드바 8개 카테고리에 각각 다른 색 점 — 학생 지원·수업 도구함은
  기존 민감구역 색(빨강·주황)을 그대로 유지, 나머지 6개는 새로 배정
- **`body { word-break: keep-all }` 전역 추가.** 결보강 배정 기준
  화면에서 "시간강사 우선" 같은 라벨이 "시\n간\n강\n사"처럼 한 글자씩
  세로로 쪼개지는 버그를 사용자가 스크린샷으로 재현해 보내옴. 이전
  라운드의 "flex-wrap + whitespace-nowrap" 땜빵은 배지·짧은 라벨에만
  적용했었는데, 이번 건 `min-w-0 flex-1` 안의 일반 `<label>` 텍스트라
  같은 패턴이 안 먹었다. 한글은 음절 단위로 줄바꿈 가능 지점이 생기는
  게 근본 원인이라, body 전체에 `word-break: keep-all`을 걸어 이
  버그 클래스 자체를 원천 차단함. Playwright로 실제 재현·수정 확인함
- "관리자" 역할 표기 → "학교관리자"로 변경(4곳: `app/(app)/layout.tsx`,
  `app/(app)/admin/page.tsx`, `app/(app)/admin/invite-form.tsx`,
  `app/invite/[token]/page.tsx`) — `/platform`의 플랫폼 최고관리자와
  헷갈리지 않게
- **실 학교(비데모)에 학기·교시가 아예 없던 버그 발견·수정.**
  `/platform`에서 새 학교를 열면 부서·결보강 가중치 기본값만 생기고
  학기(`terms`)·교시(`periods`)는 하나도 안 만들어졌다 — 즉 지금까지
  실제 학교를 새로 열면 특별실 예약·시간표가 아예 동작 안 했을
  것(테스트 안 해봐서 몰랐던 gap). `lib/platform/create-school.ts`가
  학교 개설 시 올해 학기 1개 + 4개 과정 기본 교시(9시 시작, 40분
  수업)를 자동으로 넣도록 고침. 학교 관리 화면에 과정별 탭으로 교시
  시작·종료 시각을 편집하는 표도 새로 추가(`app/(app)/admin/
  periods-form.tsx`, 저장은 그 과정 교시를 통째로 교체하는 방식)

**검증**: `npx tsc --noEmit && npx eslint . && npx vitest run`
(59개 전부 통과) `&& npx next build` 매 커밋 전에 통과 확인함.
캘린더·사이드바·결보강 폼 버그 수정은 Playwright 스크린샷으로
실제 렌더링까지 확인(devpreview-temp 임시 라우트, 확인 후 삭제).
**단, 예산 화면(`/budget`)·영수증 OCR 자체는 실제 로그인 세션·
실 Supabase 데이터가 있어야 눈으로 확인할 수 있어서 이번 세션에서는
스크린샷 검증을 못 했다 — 타입체크·빌드만 통과. 다음 세션 또는
사용자가 배포본에서 실사용 확인 필요.**
